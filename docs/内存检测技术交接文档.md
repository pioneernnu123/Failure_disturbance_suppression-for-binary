# 内存检测技术交接文档

## 1. 文档用途

本文档用于将内存失效扰动检测代码迁移到新项目，交代现有代码的模块边界、运行流程、数据格式、内核接口、错误注入方式、日志记录和已知实现边界。后续修改代码或文档时，应以本文档列出的实际接口和数据流为基础，不应把控制端状态更新、测试器失败、PFN定位和内核页标记合并成一个结果。

## 2. 代码基线

内存检测用户空间和内核模块代码位于：

```text
Failure_disturbance_suppression/
```

当前分支为 `main`，核对时的最新提交为：

```text
7e50228 userspace: reduce memtester console output
```

与内核模块匹配的 SG2042 6.1 内核源码位于：

```text
sg2042-vendor-kernel-6.1/
```

当前分支为 `main`，包含 RAMpage 支持的提交为：

```text
6e34c4db5a12 Add RAMpage support for SG2042 kernel
```

`RAMpage_on_EulixOS/` 是参考代码，不是本项目的修改目标。迁移时应保留它的原始内容，不将本项目修改回写到该目录。

## 3. 总体架构

项目由四部分组成：

1. SG2042 6.1 内核修改：导出外部模块需要的伙伴分配器和 memory cgroup 符号，开启 `CONFIG_MEMORY_FAILURE`。
2. `phys_mem` 内核模块：接收PFN申请，尝试从伙伴系统取得指定空闲页，建立用户空间映射，并提供PFN故障标记接口。
3. 用户空间调度程序：读取物理页信息，选择测试范围，批量申请页面，维护页面状态，调用测试器并处理失败页。
4. 改造后的 `memtester`：继承已打开的 `/dev/phys_mem` 文件描述符，直接测试 RAMpage 映射，通过独立结果通道返回失败相对页号。

主数据流如下：

```text
/proc/iomem + /proc/kpageflags + /proc/kpagecount
                         |
                         v
                 确定PFN范围和状态
                         |
                         v
             通过IOCTL向 /dev/phys_mem 请求PFN
                         |
                         v
               内核模块返回申请结果
                         |
                         v
              mmap成功申请的页面
                         |
                         v
          memtester继承同一设备FD并逐页测试
                         |
                         v
            结果FD返回失败相对页号
                         |
                         v
          映射顺序将相对页号转换为PFN
                         |
                         v
       IOCTL提交失败PFN，内核调用 SetPageHWPoison
```

## 4. 目录与模块职责

### 4.1 内核模块

```text
rampage/module/
├── main.c
├── file_operations.c
├── mmap_phys.c
├── page_claiming/
├── include/
├── Makefile
└── rebuild.sh
```

- `main.c`：注册 `phys_mem` 字符设备，创建 `/dev/phys_mem`，管理设备和会话对象。
- `file_operations.c`：实现 `open`、`release`、`read`、`llseek`、`ioctl` 和 `mmap` 的状态分发。
- `mmap_phys.c`：将已成功申请的物理页映射到用户空间VMA。
- `page_claiming/page_claiming.c`：校验PFN是否属于 `System RAM`，处理批量PFN申请和故障标记。
- `page_claiming/free_buddy_page_claiming.c`：从伙伴分配器中取得指定的空闲页。
- `include/phys_mem.h`：定义IOCTL、请求结构、状态结构和页面来源标志。
- `rebuild.sh`：编译模块，卸载已加载的同名模块，加载新模块，设置设备和 `/proc/kpage*` 权限。

## 6. phys_mem内核接口

### 6.1 设备与会话状态

模块加载后创建：

```text
/dev/phys_mem
```

每次打开设备都创建一个独立会话。会话状态为：

```text
CLOSED -> OPEN -> CONFIGURING -> CONFIGURED -> MAPPED
```

- `OPEN`：允许提交PFN申请。
- `CONFIGURING`：内核正在处理PFN请求。
- `CONFIGURED`：请求处理完成，可读取申请结果并建立映射。
- `MAPPED`：至少存在一个该会话的VMA映射。

内核模块通过会话信号量保护状态和申请数据。

### 6.2 PFN请求协议

用户空间使用 `PHYS_MEM_IOC_REQUEST_PAGES` 提交：

```c
struct phys_mem_request {
    unsigned long protocol_version;
    unsigned long num_requests;
    struct phys_mem_frame_request *req;
};
```

单个PFN请求为：

```c
struct phys_mem_frame_request {
    unsigned long requested_pfn;
    unsigned long allowed_sources;
};
```

当前协议版本为1。用户空间调度器传入的页面来源为 `SOURCE_FREE_BUDDY_PAGE`。

内核端先检查PFN是否通过 `pfn_valid()`，再检查该页的完整物理地址区间是否位于名称为 `System RAM` 的项层 `iomem_resource` 资源中。

对合法PFN，当前启用的申请方法顺序为：

```text
try_claim_free_buddy_page
ignore_difficult_pages
```

伙伴页申请代码检查页计数和 `PageBuddy`，在 `lruvec->lru_lock` 和 `zone->lock` 保护下从对应 `free_area` 链表删除目标页，更新伙伴分配器统计，调用 `mm_buddy_expand()` 处理高阶块的其余部分，再将目标页准备为已分配页。

### 6.3 PFN请求结果

内核为每个请求生成：

```c
struct phys_mem_frame_status {
    struct phys_mem_frame_request request;
    unsigned long long vma_offset_of_first_byte;
    unsigned long pfn;
    unsigned long long allocation_cost_jiffies;
    unsigned long actual_source;
    struct page *page;
};
```

成功申请的页按成功顺序获得连续的VMA偏移，每页增加 `PAGE_SIZE`。申请失败的记录将 `page` 和PFN结果置空，不占用映射偏移。

用户空间通过读取设备获得整个状态数组。

### 6.4 mmap

用户空间只对成功申请的页面建立映射。内核使用 `remap_pfn_range()` 将每个成功页映射到它的 `vma_offset_of_first_byte`，并为VMA设置：

```text
VM_DONTEXPAND
VM_DONTDUMP
VM_IO
```

映射页使用 `pgprot_noncached()`。第一个VMA打开后会话转为 `MAPPED`，最后一个VMA关闭后回到 `CONFIGURED`。

### 6.5 故障页标记

用户空间通过 `PHYS_MEM_IOC_MARK_FRAME_BAD` 提交：

```c
struct mark_page_poison {
    unsigned long protocol_version;
    unsigned long bad_pfn;
};
```

当前协议版本为1。会话必须处于 `CONFIGURED` 或 `MAPPED`。内核端当前直接执行：

```c
SetPageHWPoison(pfn_to_page(request->bad_pfn));
```

该接口的当前实现只设置 `HWPoison` 页标志。用户空间没有把返回值作为独立字段写入日志；`ioctl` 失败时由 Python 的 `fcntl.ioctl` 抛出异常。

## 7. 用户空间页面状态

### 7.1 状态结构

每个PFN对应一条 `FrameStatus`：

```text
last_successful_test
last_failed_test
last_claiming_time_jiffies
last_claiming_attempt
num_errors
last_successful_claiming_method
```

状态记录使用 `ctypes.Structure`，并直接映射到二进制状态文件。修改结构字段等于修改文件中的对应记录。

默认全局状态文件为：

```text
/tmp/memtest_status
```

局部模式强制使用：

```text
/tmp/rampage_memtest_status_local
```

状态文件的记录数始终等于 `/proc/kpageflags` 描述的物理页框总数。局部模式只限制统计和测试的PFN范围，不会把状态文件缩小为局部范围的记录数。

### 7.2 时间戳

状态时间戳为：

```text
int(Unix秒数 × 100)
```

转换回文本时除以100，格式为：

```text
YYYY-MM-DD HH:MM:SS
```

### 7.3 状态更新

当内核返回记录中的PFN能够在本批状态字典中找到时，用户空间更新对应记录的 `last_claiming_attempt`。当前内核对申请失败的记录将返回PFN设为0，因此一般的申请失败页不会按原请求PFN更新 `last_claiming_attempt`。

对申请成功的页：

- 保存 `allocation_cost_jiffies`；
- 保存 `actual_source`；
- 测试成功时将 `num_errors` 设为0，更新 `last_successful_test`；
- 测试失败时将 `num_errors` 加1，更新 `last_failed_test`。

成功测试不会清除历史 `last_failed_test`，失败测试也不会清除历史 `last_successful_test`。

### 7.4 调度过滤条件

`SlowScheduler.should_test()` 当前过滤：

```text
RESERVED：bit 32
NOPAGE：bit 20
```

当前调度代码没有在该条件中检查 `HWPOISON` 的bit 19。后续文档不能写成“调度器根据 `HWPOISON` 标志跳过页面”，除非先修改代码。

其他页面的判断条件为：

```text
当前时间 - last_successful_test > 最大未测试时间
```

局部模式将该间隔设为0。

## 8. 全局模式与局部模式

### 8.1 全局模式

默认模式为 `full`。扫描范围为：

```text
[0, /proc/kpageflags页框总数)
```

程序进入无限循环，每轮先统计状态，再运行 `Buddy-Claimer`。一轮中单次完整测试的默认时间为300秒。若与上轮相比 `tested` 数量不变且没有设置不等待，程序使用1、2、4秒逐步增长的等待，上限500秒。

### 8.2 局部模式

局部模式要求用户提供最大内存范围。可接受的单位为 `K`、`M`、`G`、`T`，也允许 `KiB`、`MiB`、`GiB`、`TiB` 形式。

程序遍历 `/proc/iomem` 中名称精确等于 `System RAM` 的区间，选择PFN数量最多的区间。起始地址向上对齐到页，结束位置同时受 `System RAM` 结束、物理页框总数和用户上限限制。

局部模式强制：

```text
strategy = slow
status_file = /tmp/rampage_memtest_status_local
retest_time = 0
no_delay = True
```

完成一次范围遍历后，若实际申请并测试的页面数大于0，进程退出码为0；否则为1。

### 8.3 页框总数获取

`/proc/kpageflags` 不提供可直接使用的文件大小。当前 `num_frames()` 从头到尾逐条读取8字节记录后，使用读取位置计算PFN总数。在大内存服务器上，这一步依然遍历全部 `/proc/kpageflags`，不受局部最大内存范围限制。

## 9. SlowScheduler实现

### 9.1 批量与块大小

调度器按PFN递增遍历。内部的申请块上限为512个页，连续512个不满足条件的PFN也会触发已收集页面的处理。

`frames-per-check` 控制每个调度节拍尝试处理的页面数。控制台的 `Tested` 数量不是请求页数，而是内核成功申请并交给测试器的页数。

### 9.2 映射不变式

用户空间对内核返回值强制检查：

- 成功记录中的 `pfn` 必须等于 `requested_pfn`；
- PFN必须存在于本批状态字典；
- VMA偏移必须按 `PAGE_SIZE` 对齐；
- 映射页号不得重复；
- 映射页号必须等于 `0..N-1`，不得存在空洞。

符合条件后，按映射页号构造 `claimed_physaddr`，列表中的第 `i` 项与映射中的第 `i` 页一一对应。

### 9.3 失败偏移验证

测试器返回的每个失败偏移必须：

- 是整数；
- 大于或等于0；
- 小于当前映射长度；
- 是 `PAGE_SIZE` 的整数倍。

通过检查后使用：

```text
page_index = error_offset / PAGE_SIZE
```

确定失败映射页，再取得同一映射位置的PFN。

## 10. memtester映射模式

### 10.1 命令构造

测试包装器实际执行：

```text
/usr/local/bin/memtester
    [用户额外参数]
    -F <mapped_fd>
    -R <result_fd>
    -c <injection_type>
    <mapping_length>B
    1
```

- `-F`：已打开的 `/dev/phys_mem` 会话文件描述符。
- `-R`：临时结果文件描述符。
- `-c`：该次调用的注入类型。包装器把该参数放在额外参数之后，因此它覆盖额外参数中更早的 `-c`。
- `<mapping_length>B`：使用字节作为单位的映射总长度。
- `1`：测试循环次数。

常用额外参数 `-i 5` 表示当前映射中从0起算的第6页。它不是PFN 5，也不是整个扫描范围的第6页。若当前批次成功映射的页少于6页，该批次不会执行注入。

### 10.2 映射结构

`memtester` 使用 `mmap(MAP_SHARED)` 重新映射继承的设备FD。它逐页处理映射，对每页执行：

```text
bufa = 当前页起始
bufb = 当前页的一半位置
count = 半页 / sizeof(unsigned long)
```

`Stuck Address` 使用完整页长度；比较类测试在两个半页对照区域之间进行。

### 10.3 测试项

未通过 `MEMTESTER_TEST_MASK` 限制时，每个映射页依次执行：

```text
Stuck Address
Random Value
Compare XOR
Compare SUB
Compare MUL
Compare DIV
Compare OR
Compare AND
Sequential Increment
Solid Bits
Block Sequential
Checkerboard
Bit Spread
Bit Flip
Walking Ones
Walking Zeroes
8-bit Writes
16-bit Writes
```

注入类型只决定哪个测试函数修改目标页，不会让测试器只执行对应的一项测试。

### 10.4 注入类型

```text
0  None
1  Stuck Address
2  Compare XOR
3  Solid Bits
4  Checkerboard
5  Walking Zeroes
6  Compare OR
7  8-bit Writes
```

类型1至7的当前注入实现都在目标相对页中执行：

```c
bufa[i] ^= 0x1;
```

即翻转 `bufa` 中数据的最低有效位，但翻转发生在不同的测试函数中：

| 类型 | 修改位置 |
|---|---|
| 1 | `test_stuck_address()` 写入地址模式后 |
| 2 | `test_xor_comparison()` 完成异或运算后 |
| 3 | `test_solidbits_comparison()` 每轮模式写入后 |
| 4 | `test_checkerboard_comparison()` 每轮模式写入后 |
| 5 | `test_walkbits0_comparison()` 每轮模式写入后 |
| 6 | `test_or_comparison()` 完成或运算后 |
| 7 | `test_8bit_wide_random()` 按字节写入后 |

`inject_once` 变量虽然存在，但当前注入函数没有使用它阻止后续注入。因此不能把一次控制端输入等同为一次实际注入。

### 10.5 结果协议

结果FD的格式为：

```text
RAMPAGE_RESULT_V1 <page_count>
BAD <page_index>
BAD <page_index>
END
```

包装器要求：

- 第一行页数与当前映射页数完全相等；
- 最后一行为 `END`；
- 中间每行只能是 `BAD` 加十进制页号；
- 失败页号不能越界或重复。

允许的 `memtester` 返回码为0、2、4和6。返回码为0时不得有 `BAD`；返码非0时必须有 `BAD`。否则包装器抛出 `RuntimeError`，不把该结果解释为坏页。

## 11. 动态注入控制

默认共享状态文件为：

```text
/tmp/rampage_memtester_injection_type
```

测试包装器构造时，将初始类型写入该文件。未指定初始类型时使用0。每次开始新的 `memtester` 子进程前重新读取状态文件。

控制程序写入时先创建包含进程号的临时文件，写入并 `fsync()` 后使用 `os.replace()` 替换正式状态文件。

控制端的类型更新是异步状态修改，没有与主测试进程交换“本次注入已执行”的确认消息。新类型只对下一次及后续 `memtester` 调用生效。若不切换回0，后续满足目标页条件的批次仍会使用当前类型。

## 12. 控制台与日志

### 12.1 主测试控制台

局部模式启动时输出：

```text
局部测试模式：在指定范围内执行完整测试流程
自动选择 System RAM：PFN ... - ...
本次完整处理范围：PFN ... - ...，共 ... MiB（上限 ...）
完成整个指定范围后自动退出
```

随后输出调度器名称、`local pass 1`、PFN统计开始信息和页面统计摘要。

当前测试包装器在每次调用 `memtester` 前输出：

```text
当前错误类型：<name>
```

进度输出为：

```text
Tested <total> frames in <seconds>s. fps=<fps> (this batch: <count> in <seconds> s: fps=<fps>)
```

坏页在未配置串口时输出：

```text
[WARNING] bad frame at pfn <8位十六进制PFN> (no serdev)
```

配置串口时，坏页信息写入串口，同时将已测试PFN压缩为范围列表后写入串口。

局部测试结束时输出：

```text
局部范围测试完成：成功申请并测试 <count> 个页面，用时 <seconds> 秒
```

当前代码不在主控制台输出完整 `memtester` 命令或详细日志路径。

### 12.2 页面统计日志

`--logfile` 指定页面统计日志。局部模式未指定时默认为用户空间目录下的：

```text
rampage-local.log
```

日志以追加方式写入。调度统计重置时写入：

```text
---log reset---
```

到达报告周期或调度结束时写入：

```text
pass: <frames> frames <seconds> seconds (<fps> fps) - chunk: <frames> frames <seconds> seconds (<fps> fps)
```

页面状态统计写入：

```text
==== stats at <Unix秒时间戳> ====
<testable/tested/recently tested/untested/untestable/nopage/have seen errors>
^^^^ stats ^^^^
```

该日志不记录注入类型、测试器逐页结果、`FAILURE`、`Mapped failure` 或坏页警告。

### 12.3 memtester详细日志

详细日志固定为用户空间目录下的：

```text
memtester_execution_details.log
```

每次调用追加：

```text
==================== Run at YYYY-MM-DD HH:MM:SS ====================
Injection type: <number> (<name>)
Claimed PFNs: <hex PFN list>
Command: <actual command>
```

`memtester` 的标准输出和标准错误都重定向到该文件，包括版本、页大小、命令行注入页、注入类型、每页的测试项、`ok`和 `FAILURE`。

结果协议解析完成后，每个失败页追加：

```text
Mapped failure: page=<relative index> PFN=<hex PFN>
```

`RAMPAGE_RESULT_V1`、`BAD`和 `END` 只写入临时结果文件，不写入详细日志。

### 12.4 控制端输出

控制端启动后显示0至7类型菜单。输入有效类型后输出：

```text
当前错误类型：<name>
```

该输出只说明状态文件已更新，不是注入执行回执。

## 13. 页面统计定义

页面状态摘要的计算方式为：

- `tested`：`last_successful_test > 0` 或 `last_failed_test > 0`。
- `recently tested`：最近成功或失败时间大于当前重测时间界限。
- `untestable`：未测试页且 `/proc/kpageflags` 的 `RESERVED` bit 32 置位。
- `nopage`：未测试页且 `NOPAGE` bit 20 置位。
- `untested`：未测试页，且不属于上述两类。
- `have seen errors`：当前 `num_errors > 0`。
- `testable frames`：`tested + untested`。

`have seen errors` 不是永久历史错误总数，因为一个页面之后测试成功时，`num_errors` 会被重置为0。

状态文件不会在每次运行时自动清空，因此启动阶段看到的 `tested` 和 `have seen errors` 可能来自以前的运行。

## 16. 必须保留的实现事实

迁移后修改文档时，必须保留以下事实，除非同时修改了代码：

1. 注入类型是共享文件中的持续状态，不是单次事件。
2. 控制端的“当前错误类型”不是注入执行成功的回执。
3. `-i 5` 是当前成功映射批次的相对页号，不是PFN。
4. 当前批次映射少于6页时，`-i 5` 不会注入。
5. 注入类型只选择修改发生的测试函数，`memtester` 仍执行其他未被测试掩码关闭的项目。
6. 失败页依赖映射顺序转换为PFN，不把相对页号直接当作PFN。
7. 页面统计日志和 `memtester` 详细日志是两个不同文件，内容不同。
8. 结果FD的 `RAMPAGE_RESULT_V1/BAD/END` 不进入详细日志。
9. 状态文件在多次运行之间保留，启动阶段的页面统计可以包含旧数据。
10. `have seen errors` 根据当前 `num_errors > 0` 计算，不是永久累计错误数。
11. 当前调度器过滤 `RESERVED` 和 `NOPAGE`，没有在 `should_test()` 中过滤 `HWPOISON`。
12. 当前内核处置是调用 `SetPageHWPoison`，不能在未新增代码的情况下写成已完成页迁移、内存热移除或硬件ECC修复。
13. 用户空间没有把页标记IOCTL的成功返回值作为单独字段写入日志。
14. 局部模式只限制扫描和统计范围，页状态文件仍按全部PFN数量创建。
15. `/proc/kpageflags` 的总PFN数获取仍需要遍历整个文件。

## 17. 已知技术债务和后续修改点

以下内容是当前代码的实际状态，可在新项目中单独评估：

1. 主测试端和控制端都会输出“当前错误类型”。如果需要只在控制端输出，必须修改测试包装器。
2. 控制端没有批次序号、注入次数、生效回执或与检测进程的同步协议。
3. `inject_once` 没有用于限制注入次数。
4. 详细日志和页面统计日志都只追加，没有日志轮转。
5. 局部状态文件不会自动清空，实验开始前是否保留历史状态需要由试验流程明确决定。
6. `handle_mark_page_poison()` 当前直接对用户提交的PFN执行 `pfn_to_page()`，该路径未复用PFN申请阶段的 `pfn_valid()` 和 `System RAM` 资源校验。
7. 用户空间在调用页标记IOCTL前先更新了页面失败状态；若IOCTL随后失败，状态文件已包含本次失败记录。
8. 页面统计中的平均最近测试时间累加的是 `last_successful_test`，但分母使用所有 `tested` 页数，包括只有失败时间的页。
9. 页面统计在 `testable frames` 为0时仍执行百分比除法，当前没有零分母保护。
10. `rebuild.sh` 将 `/dev/phys_mem` 设为0777，将 `/proc/kpage*` 设为0444，这是当前脚本行为，迁移到其他环境时需要重新评估权限策略。
