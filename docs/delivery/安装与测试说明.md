# lzu-ram 二进制包安装与测试说明

本说明供甲方使用。适用范围：同型号 SG2042、riscv64、与打包环境相同的发行版 ID 和 VERSION_ID，启动配置手工维护在 `/boot/grub/grub.cfg`。交付内核版本为 `6.1.80-lzu-ram+`。其他启动布局不能直接套用本说明。

内核、phys_mem 驱动、memtester、主程序、控制端及两组测试的可执行文件均由打包方生成。主程序、控制端和测试采用 Nuitka standalone，每个可执行目录自带 Python 运行库；甲方直接运行程序，不安装 Nuitka、编译器、Python 开发包或内核源码，也不执行 make。必须保留程序旁的全部运行库文件。

包内不交付本工程 `.py`、外置 `.pyc`、C 源码、头文件、Makefile 或构建脚本。系统依赖采用发行版二进制 RPM，它们自身可能包含解释型运行文件。工程中的压力辅助程序、Prometheus 导出程序不在本次核心扫描与自带测试交付范围。

以下按首次安装编写。已有同名但来源不同的内核、模块目录或 `/opt/Failure_disturbance_suppression-binary-riscv64` 时，应先停止旧程序、核对并备份原文件，不能将不同构建混合。每条命令成功后再继续。

## 1 验证交付文件与平台

在收到三个交付文件的目录执行：

```bash
# 校验大包是否在传输中损坏，应显示 OK。
sha256sum -c lzu-ram-1.0.tar.gz.sha256

# 解压大包；-x 解压，-z 读取 gzip，-f 后面是文件名。
tar -xzf lzu-ram-1.0.tar.gz

# 进入解压后的交付目录。
cd lzu-ram-1.0

# 查看打包时的操作系统、板卡、Python 和运行库信息。
cat 打包环境.txt

# 查看接收服务器架构，应为 riscv64。
uname -m

# 查看本机发行版 ID 和 VERSION_ID，应与打包环境一致。
cat /etc/os-release

# 查看本机板卡型号，应与打包环境一致。
cat /proc/device-tree/model
```

## 2 离线安装系统运行依赖

以下命令仍在解压后的 `lzu-ram-1.0` 目录执行：

```bash
# 仅使用包内 RPM 安装 glibc、kmod、dracut 及其运行依赖。
sudo dnf --disablerepo='*' install ./运行依赖/*.rpm
```

`--disablerepo='*'` 禁用网络软件源，适合离线安装。DNF 检查系统包依赖，不强制覆盖系统库。应用及测试使用各自目录中的 Python 运行库，不需要匹配甲方系统 Python 的小版本。[Nuitka standalone 说明](https://nuitka.net/user-documentation/user-manual.html)

## 3 安装内核和应用二进制

仍在 `lzu-ram-1.0` 目录操作。

```bash
# 备份实际使用的 GRUB 配置，保留原正常启动项。
sudo cp /boot/grub/grub.cfg /boot/grub/grub.cfg.lzu-ram安装前备份

# 阅读接收服务器自身的正常启动项。
sudo cat /boot/grub/grub.cfg

# 查看本机磁盘、文件系统标签、UUID 和挂载点，供核对启动项。
lsblk -f

# 安装已经编译好的内核镜像。
sudo cp sg2042-kernel61/boot/vmlinuz-6.1.80-lzu-ram+ /boot/

# 安装内核符号映射表，便于诊断。
sudo cp sg2042-kernel61/boot/System.map-6.1.80-lzu-ram+ /boot/

# 安装内核配置记录。
sudo cp sg2042-kernel61/boot/config-6.1.80-lzu-ram+ /boot/

# 把该版本的模块目录解压到 /lib/modules；-C 指定解压位置。
sudo tar -xzf sg2042-kernel61/内核模块.tar.gz -C /lib/modules

# 将应用二进制与运行库复制到固定运行位置；-a 保留目录结构和属性。
sudo cp -a Failure_disturbance_suppression-binary-riscv64 /opt/

# 检查主程序可执行文件和随包运行库在本机能否启动。
/opt/Failure_disturbance_suppression-binary-riscv64/app/main/rampage --help

# 检查控制端可执行文件在本机能否启动。
/opt/Failure_disturbance_suppression-binary-riscv64/app/control/injection-control --help

# 查看工程固定调用的位置是否已有旧 memtester。
ls -l /usr/local/bin/memtester
```

如果 `/usr/local/bin/memtester` 已存在，先执行这条备份命令；不存在时跳过，直接继续安装：

```bash
# 备份原 memtester，以便恢复。
sudo cp -a /usr/local/bin/memtester /usr/local/bin/memtester.安装前备份
```

```bash
# 将工程改造版 memtester 安装到主程序固定调用的位置。
sudo cp /opt/Failure_disturbance_suppression-binary-riscv64/bin/memtester /usr/local/bin/memtester

# 给予可执行文件常规运行权限。
sudo chmod 755 /usr/local/bin/memtester

# 建立本内核版本的额外模块目录。
sudo mkdir -p /lib/modules/6.1.80-lzu-ram+/extra

# 安装本次交付的 phys_mem 驱动。
sudo cp /opt/Failure_disturbance_suppression-binary-riscv64/modules/phys_mem.ko \
    /lib/modules/6.1.80-lzu-ram+/extra/

# 为目标内核生成模块依赖索引，供 dracut 和 modprobe 使用。
sudo depmod 6.1.80-lzu-ram+

# 用已安装模块为甲方本机磁盘和根文件系统制作启动文件。
sudo dracut /boot/initramfs-6.1.80-lzu-ram+.img 6.1.80-lzu-ram+

# 确认内核镜像和刚生成的启动文件都存在。
ls -l /boot/vmlinuz-6.1.80-lzu-ram+ /boot/initramfs-6.1.80-lzu-ram+.img
```

`depmod` 只生成模块索引，`dracut` 只组装本机的初始启动文件，均不编译工程。若已有同名 initramfs，应先核对、另存原文件，不能直接混用旧文件。

## 4 根据本机原条目添加 GRUB 启动项

```bash
# 编辑这台服务器实际使用的启动配置。
sudo vi /boot/grub/grub.cfg
```

在 vi 中完成以下操作：

1. 保留原正常启动项和原 default 设置；首次启动手工选择新内核。
2. 复制本机一个已经能正常启动的完整 `menuentry`，追加为新条目。
3. 将复制条目的标题改为 `OpenEuler Linux 6.1.80-lzu-ram+`；若复制项带有 `--id`，也给新条目一个不同的 id，例如 `lzu-ram-6.1.80`。
4. 新条目 linux 行只将内核文件名替换为 `vmlinuz-6.1.80-lzu-ram+`。
5. 新条目 initrd 行只将启动文件名替换为 `initramfs-6.1.80-lzu-ram+.img`。
6. 本机原有 root/search 定位、Linux 的 `root=`、console、文件系统参数、设备树等内容全部保留。
7. 输入 `:wq` 保存退出。

原条目若是 `/boot/vmlinuz...`，沿用 `/boot/` 前缀；若是 `/vmlinuz...`，沿用 `/` 前缀。GRUB 查找内核的分区定位和 Linux `root=` 的用途不同，二者都应以本机原条目为准。[GRUB 内核启动说明](https://www.gnu.org/software/grub/manual/grub/html_node/GNU_002fLinux.html)

山大实际配置中的 `set default=2`、`hd0,msdos2` 和 `root=LABEL=ROOT` 不能据此认定为甲方机器的值。实际配置与启动参数中还出现了断开的 `nvme.use_threaded_int errupts=1`，不将它作为一个完整有效的 NVMe 参数新增到甲方配置。本流程不修改打包机启动参数；这里复制的是接收服务器自身的正常启动参数。

```bash
# 保存后查看配置，核对新增项的标题、内核路径、initrd 路径和原分区参数。
sudo cat /boot/grub/grub.cfg
```

系统有 `grub-script-check` 时，可额外检查语法：

```bash
# 检查 GRUB 语法；这不验证磁盘路径是否真实存在。
sudo grub-script-check /boot/grub/grub.cfg
```

若发行版将命令命名为 `grub2-script-check`，使用该名称。未安装该工具时人工核对；本流程不依赖 grubby，也不执行自动重新生成 grub.cfg 的命令。

通过串口或远程管理控制台进行首次启动，确保能选择新增条目及保留的原条目：

```bash
# 重启后在 GRUB 菜单选择 OpenEuler Linux 6.1.80-lzu-ram+。
sudo reboot
```

重启登录后：

```bash
# 确认实际进入交付内核，必须输出 6.1.80-lzu-ram+。
uname -r
```

## 5 加载驱动并检查环境

```bash
# 加载已经安装的 phys_mem 内核模块。
sudo modprobe phys_mem

# 等待系统设备事件处理完毕。
sudo udevadm settle

# 仅允许 root 访问物理内存测试设备，测试命令也以 sudo 执行。
sudo chmod 600 /dev/phys_mem

# 查看 phys_mem 是否已经加载。
lsmod | grep phys_mem

# 确认物理内存测试设备存在。
ls -l /dev/phys_mem

# 检查已安装驱动的版本标识，应以 6.1.80-lzu-ram+ 开头。
modinfo -F vermagic phys_mem

# 检查 memtester 动态库依赖，应没有 not found。
ldd /usr/local/bin/memtester

# 查看物理内存映射，应能看到有效的 System RAM 地址。
sudo head /proc/iomem
```

## 6 运行工程自带的二进制测试

```bash
# 执行临时文件映射测试，覆盖错误类型 0 至 7，不操作真实物理页。
/opt/Failure_disturbance_suppression-binary-riscv64/tests/test_rampage_fd/test_rampage_fd

# 执行映射、结果解析和 PFN 对应逻辑的五项测试。
/opt/Failure_disturbance_suppression-binary-riscv64/tests/test_memtester_mapping/test_memtester_mapping
```

第一组应输出 `RAMpage inherited-fd smoke test: OK`，其中类型 0 无坏页、类型 1 至 7 均定位临时映射中的相对页 1；第二组应显示 `Ran 5 tests`、`OK`。二进制包中不运行源码测试入口。模拟测试通过后，还需真实设备测试。

## 7 执行真实物理页测试

真实注入会改变申请到的物理页内容，检测后驱动会执行页错误标记操作。应在验收测试服务器执行；各真实注入轮次之间重启并重新选择交付内核、加载驱动，恢复测试条件。

### 7.1 不注入错误，执行一轮局部扫描

```bash
# 进入主程序所在目录。
cd /opt/Failure_disturbance_suppression-binary-riscv64/app/main

# 在限定的 System RAM 地址范围内执行一轮无注入扫描，完成后退出。
sudo ./rampage -t memtester \
    --scan-mode=local --max-memory=256M --frames-per-check=50 \
    --memtester-inject-type=0 \
    --logfile=/opt/Failure_disturbance_suppression-binary-riscv64/app/main/不注入错误统计.log

# 紧接上一条命令查看退出码，应为 0。
echo $?
```

参数含义：

| 参数 | 用途 |
| --- | --- |
| `-t memtester` | 选择工程改造后的 memtester 算法，必须明确指定。 |
| `--scan-mode=local` | 执行一轮限定范围扫描后退出。 |
| `--max-memory=256M` | 扫描所选 System RAM 段中最多 256 MiB 的地址范围。 |
| `--frames-per-check=50` | 每批最多申请 50 个候选页。 |
| `--memtester-inject-type=0` | 不注入错误。 |
| `--logfile` | 指定页面统计日志的位置。 |

应看到“局部范围测试完成”，成功申请并测试的页数必须大于 0。健康硬件、无历史注入影响时不应报告 FAILURE 或 bad frame。页数为 0 不算通过；可能需要在有空闲页的测试环境中增大 `--max-memory` 后再测。

`--max-memory=256M` 限制的是扫描的物理地址范围，不是程序总内存占用上限；程序仍按全机 PFN 数建立状态文件。

### 7.2 注入类型 1，验证检测和 PFN 对应

```bash
# 对局部范围执行类型 1 注入；-i 0 指每个成功映射批次的相对页 0。
sudo ./rampage -t memtester \
    --scan-mode=local --max-memory=256M --frames-per-check=50 \
    --memtester-args="-i 0" --memtester-inject-type=1 \
    --logfile=/opt/Failure_disturbance_suppression-binary-riscv64/app/main/类型1注入统计.log

# 查看最近 100 行 memtester 详细执行记录。
sudo tail -n 100 /opt/Failure_disturbance_suppression-binary-riscv64/app/main/memtester_execution_details.log

# 查看最近的内核消息，检查是否发生驱动或内核异常。
sudo dmesg | tail -n 50
```

新增的参数 `--memtester-args="-i 0"` 向 memtester 指定注入相对页 0，`--memtester-inject-type=1` 选择 Stuck Address 错误类型。`-i 0` 不是物理 PFN。类型 1 会持续影响后续满足条件的批次，不是整轮仅注入一次。

核对本轮日志中的 `Injection type: 1`、`Claimed PFNs`、预期 FAILURE，控制台中的 `bad frame at pfn` 应与映射对应；扫描应完成且无 IOCTL 或内核异常。详细日志与 `--logfile` 统计日志是不同文件，历史日志会追加，须按本轮时间核对。

代码在检测失败后调用页标记接口，内核路径设置 HWPoison。现有日志不单独确认每次页标记 IOCTL 成功，不能将检测日志直接当成页迁移、页下线或硬件修复已经完成的证明。

### 7.3 测试运行中切换类型

先重启、选择交付内核，再执行第 5 节加载驱动命令。终端 A：

```bash
# 进入主程序目录。
cd /opt/Failure_disturbance_suppression-binary-riscv64/app/main

# 持续扫描，初始不注入；允许页重复测试，以观察运行中的类型切换。
sudo ./rampage -t memtester \
    --frames-per-check=50 --retest-time=0 --no-delay \
    --memtester-args="-i 0" --memtester-inject-type=0 \
    --logfile=/opt/Failure_disturbance_suppression-binary-riscv64/app/main/持续扫描统计.log
```

`--retest-time=0` 允许立即重测页面；`--no-delay` 取消无进展时的退避等待。本模式持续运行，使用 Ctrl+C 结束。

终端 B：

```bash
# 进入控制端所在目录。
cd /opt/Failure_disturbance_suppression-binary-riscv64/app/control

# 启动交互式错误类型控制端。
sudo ./injection-control
```

先输入 `1` 并回车，观察之后调用的 memtester 日志；再输入 `0` 并回车，观察后续批次恢复无注入。类型 2 至 7 也可按同样方式选择。输入 `q` 只退出控制窗口，不会停止扫描或自动复位类型。控制端写入成功不等于注入已执行，以之后实际的 memtester 日志为准。

## 8 验收与后续启动

| 检查项 | 通过标准 |
| --- | --- |
| 内核和驱动 | uname -r 正确；模块正常加载；设备存在；动态库无缺失。 |
| 自带 memtester 测试 | 类型 0 至 7 全部通过并输出 OK。 |
| 自带映射测试 | 5 项全部通过。 |
| 真实无注入扫描 | 测试页数大于 0，正常结束，健康硬件与干净状态下无错误。 |
| 真实类型 1 注入 | 本轮类型、FAILURE 和 PFN 对应，扫描完成，无 IOCTL 或内核异常。 |
| 动态类型控制 | 后续 memtester 日志实际显示 0、所选类型、0 的切换。 |

保留打包环境、实际内核版本、自测输出、主程序控制台输出、统计日志、memtester 详细日志和本轮 dmesg。局部模式状态文件为 `/tmp/rampage_memtest_status_local`；需要独立轮次时，停止测试后另存旧状态和日志，避免混入历史统计。

首次启动保留原默认项，之后每次重启应选择交付内核并重新加载驱动。验收通过后，如需默认进入本内核，可再次编辑同一个配置：

```bash
# 在验收通过后设置默认条目，保留旧内核条目用于回退。
sudo vi /boot/grub/grub.cfg
```

将已有 `set default=...` 改为新条目的标题（适用于本说明追加的顶层条目）：

```grub
set default='OpenEuler Linux 6.1.80-lzu-ram+'
```

每次重启后加载驱动：

```bash
# 加载测试驱动。
sudo modprobe phys_mem

# 等待设备节点就绪。
sudo udevadm settle

# 设置测试设备的 root 访问权限。
sudo chmod 600 /dev/phys_mem
```

如需回退，停止扫描与控制端，执行：

```bash
# 在没有程序占用设备时卸载驱动。
sudo modprobe -r phys_mem

# 重启，并在 GRUB 选择原正常内核。
sudo reboot
```

原启动项和 `grub.cfg.lzu-ram安装前备份` 均保留；如原 memtester 做过备份，可用该备份恢复。甲方不需要编译即可执行上述流程；该服务器是否实际安装验收通过，以完成本机启动、驱动和真实测试的结果为准。
